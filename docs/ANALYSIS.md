# 中文赛事分析与公开试运行

在比赛详情选择“阅读 AI 赛事分析”。看板直接显示足球模型概率，报告使用同一场比赛的赛前事实。没有配置 DeepSeek 时，Python demo 和 GitHub Pages 均可阅读基础数据解读。每份报告提供事实核对入口。已核实的真实 AI 生成报告单独标明生成方。

## 运行方式

| 入口 | 凭据 | 能力 |
|---|---|---|
| Python demo | 无 | 查看比分模型、赛前事实和基础解读，查询赛程与成绩 |
| GitHub Pages | 访客无需凭据 | 读取独立核验批次，与该批次事实相符的共享 AI 报告可随站点镜像 |
| Cloudflare 免费公测站 | 运营方配置 D1、DeepSeek 和访客限额密钥 | 免费阅读、共享报告、同场连续追问、预算限额与故障降级 |

查看 [Cloudflare 的部署说明](../cloudflare/README.md)。将生产项目的 production branch 设为 `epl-v1`。完成账户内的免费项目与 D1 准备后，在 GitHub Actions 设置仓库变量 `EPL_CF_PAGES_PROJECT`、`CLOUDFLARE_ACCOUNT_ID`、`CLOUDFLARE_D1_DATABASE_ID` 和完成价格核对后的 `EPL_PRICING_VALID_UNTIL`，另通过 Actions secret 设置 `CLOUDFLARE_API_TOKEN`。DeepSeek 密钥与访客 HMAC 密钥存放在 Cloudflare 的服务端 secrets。只给发布 token 该项目所需的 Pages 和 D1 权限。未设置项目名时，现有 GitHub 部署继续独立运行。

Pages 工作流先核验固定提交，再部署同一静态包及同域函数，并核对返回的提交。仅当前轮已批准的比赛有资格生成共享报告。GitHub 镜像按比赛和事实哈希复核生成的每段文字。历史赛季的事实随静态包发布，已回放的终场比分只在明确复盘时读取。

本地 Python 服务可通过环境变量 `EPL_ANALYSIS_ORIGIN` 连接同一网关，支持其 HTTPS 来源或本机 Wrangler HTTP 服务。两端必须使用相同的比赛事实与版本。更换资料批次后重新打开报告。准备真实调用前，可用离线回归覆盖服务协议、预算和输出引用；真实验收单独记录供应商调用及公开地址。

## 成本、可用性和发布

报告与追问分别使用每月 20 元和 30 元的人民币预算，总计 50 元。D1 先按保守的输入、输出用量预留，再核对供应商用量；请求结果不明时保留预留。访客的实时 AI 追问每天最多 5 次。历史浏览、基础查询与已有报告可继续使用。批次发布时间与分析资料版本分别记录，相同事实能复用已有报告。

公网运行后，应从实际电信、移动、联通接入点验证匿名浏览、阅读、追问与下载。7 天可用率、公开 SHA 延迟、真实 DeepSeek 成功响应、独立模型 A 实赛结算和市场配对分别记录。上线前由运营者核对面向境内公众的模型登记、公示与标识要求，并在服务页面填入实际公示资料。[网信办公告](https://www.cac.gov.cn/2026-09/14/c_1791136833136332.htm)

报告文本存在 D1，GitHub Pages 另有可复算数据及已核对的镜像。变更网关或计量表之前备份 D1；用备份恢复至独立测试库后，核对本月两项已用及预留费用、访客计数、缓存报告数与事实哈希。回滚先关闭新生成，保留当前计量库。恢复服务使用最新已核验的静态批次并保留待核用量记录。

探针安装命令、异常指标、验收阈值与 D1 恢复核验步骤见[国内三网七天验收](MONITORING.md)。
